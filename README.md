# paper-to-code-learning

把一篇论文真正读到代码里。

`paper-to-code-learning` 是一个面向 Codex 的中文学习 Skill，用来把本地论文、源码、实验配置和讨论，组织成一条可复查的学习路径：

```text
论文主张 → 机制数据流 → 真实源码 → 最小验证 → 实验设计
```

它适合那些“看过论文，但还不知道代码在哪里；看过代码，却不知道它为什么这样设计”的系统学习任务。

## 它能帮你做什么？

- 从论文问题出发，而不是从源码目录开始罗列类名。
- 从一个朴素但正确的实现开始，逐步引出真正的系统瓶颈。
- 用架构图、数据流、对比表、伪代码和数值走查降低理解门槛。
- 把论文机制映射到真实文件、符号和源码片段。
- 明确区分论文事实、源码事实、教学例子、合理推断和待核验内容。
- 设计从正确性 smoke test 到论文规模复现的实验配置。
- 不把“读到了接口”写成“已经实现”，也不把“建议实验”写成“已经复现”。

## 五阶段学习闭环

| 阶段 | 产物 | 核心问题 |
|---|---|---|
| Step 0 | 范围与证据边界 | 我们到底有什么材料，哪些结论可以证明？ |
| Step 1 | 论文结构化解构 | 论文解决了什么问题，实验怎样支持它？ |
| Step 2 | 第一性原理与批判性问答 | 为什么需要这个机制，它在哪些条件下会失效？ |
| Step 3 | 论文—源码综合长文 | 一个请求怎样从论文设计走到真实代码？ |
| Step 4 | 实验设计与推荐配置 | 怎样验证主张，而不是只把系统跑起来？ |

Step 3 是本 Skill 的核心：它采用问题驱动的工程叙事，把“朴素实现 → 瓶颈 → 架构 → 数据流 → 源码 → 不变量 → 实验”串成一篇可以独立阅读的技术文章。

## 快速使用

在 Codex 中显式调用：

```text
$paper-to-code-learning
```

然后提供：

1. 本地论文 PDF 或论文路径；
2. 代码仓库或源码目录；
3. 想重点理解的机制、疑问或已有笔记；
4. 是否需要实验配置。

一个典型请求：

```text
$paper-to-code-learning

论文在 ./paper.pdf，代码在 ./project。
请按完整五阶段分析，重点解释论文中的缓存调度如何落到源码，最后只给出远程实验配置，不要在本地运行实验。
```

## 推荐的仓库结构

```text
paper-to-code-learning/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── reproduction-ladder.md
    ├── source-map-template.md
    └── task-card-template.md
```

`SKILL.md` 定义主流程，`references/` 提供证据地图、任务卡和复现阶梯等可复用模板。

## 适合哪些任务？

- LLM 推理引擎、KVCache、分布式训练和系统论文；
- 论文提出新机制，但开源代码版本已经演进的项目；
- 想从“会背论文”走向“能沿源码调试”的学习；
- 需要为远程 GPU 集群设计实验，却暂时不能在本地运行；
- 希望把零散阅读笔记沉淀为可持续维护的技术文章。

## 证据边界

本 Skill 有意保持克制：

```text
接口存在       ≠ 完整机制已经实现
源码结构清晰   ≠ 并发正确性已经证明
实验配置完整   ≠ 实验已经运行
论文数字可信   ≠ 不同硬件上可以直接复现
```

这让最终笔记不仅“读起来顺”，也能被别人沿着文件、符号和实验条件重新检查。
